```csharp
using System;

namespace ConsoleApp1
{
  // 1. 定义委托
    public delegate void MyEventHandler(object sender, EventArgs e);
    
    class Publisher
    {
        // 2. 声明事件
        public event MyEventHandler MyEvent;

        // 3. 触发事件的方法
        public void RaiseEvent()
        {
            MyEvent?.Invoke(this, EventArgs.Empty);
        }
    }

    class Subscriber
    {
        public void OnMyEvent(object sender, EventArgs e)
        {
            Console.WriteLine("事件被触发了！");
        }
    }

    class Program
    {
        static void Main()
        {
            Publisher publisher = new();
            Subscriber subscriber = new();

            publisher.MyEvent += subscriber.OnMyEvent;  // 订阅
            publisher.RaiseEvent();                      // 触发
            publisher.MyEvent -= subscriber.OnMyEvent;  // 取消订阅
        }
    }
}
```

事件是 C# 中实现观察者模式的核心机制，它基于委托（Delegate）构建，用于在对象之间实现松耦合的通信。

事件是一种特殊的委托，它允许一个类（发布者/Publisher）在发生某些事情时通知其他类（订阅者/Subscriber）。

# C# 事件（初学者版）总结

> 用生活例子理解事件：**一个人喊话，其他人自愿来听。**

---

## 一、事件的核心思想

事件就是一句话：

> **"我这里发生了一件事，谁关心谁就来听。"**

- **喊话的人**不需要知道谁在听、听了要干嘛
- **听的人**自己决定要不要响应、怎么响应

---

## 二、三个角色（大白话版）

| 专业术语 | 大白话 | 例子 |
|---------|--------|------|
| 发布者（Publisher） | 喊话的人 | 外卖小哥、按钮 |
| 订阅者（Subscriber） | 听的人 | 短信系统、主程序 |
| 事件（Event） | 那句喊话 | "我送到了！" |
| 事件处理器 | 听的人听到后干的事 | 发短信、记日志 |

---

## 三、生活例子：外卖小哥

**需求**：骑手送完外卖后，短信系统和平台系统要各自做事。

**思路**：骑手只需要喊一声"我送到了"，其他人自己来听。

### 代码示例

```csharp
// 外卖小哥（发布者）
class 外卖小哥
{
    // 声明一个事件：我能喊"送到了"
    public event Action 送到了;

    public void 送外卖()
    {
        Console.WriteLine("骑手：我送到了！");
        送到了?.Invoke();  // 喊一声
    }
}

// 短信系统（订阅者）
class 短信系统
{
    public void 发短信()
    {
        Console.WriteLine("短信系统：给顾客发短信");
    }
}

// 平台系统（订阅者）
class 平台系统
{
    public void 通知平台()
    {
        Console.WriteLine("平台：标记订单已送达");
    }
}

// 使用
var 骑手 = new 外卖小哥();
var 短信 = new 短信系统();
var 平台 = new 平台系统();

// 让它们"听"骑手的喊话
骑手.送到了 += 短信.发短信;
骑手.送到了 += 平台.通知平台;

// 骑手送外卖
骑手.送外卖();
```

**输出：**

```
骑手：我送到了！
短信系统：给顾客发短信
平台：标记订单已送达
```

> 骑手完全不知道短信系统和平台系统的存在，他只是喊了一声。

---

## 四、为什么不用普通方法调用？

**笨办法：**

```csharp
骑手.送外卖();
短信.发短信();
平台.通知平台();
```

**问题：**

| 问题 | 说明 |
|------|------|
| 耦合太紧 | 骑手代码必须知道短信、平台的存在 |
| 改一处动全身 | 想加"给顾客打电话"，要改骑手的代码 |
| 不能动态增删 | 想临时关闭短信通知？做不到 |

**用事件之后：**

```csharp
骑手.送到了 += 短信.发短信;   // 想加就加
骑手.送到了 -= 短信.发短信;   // 想删就删
```

骑手的代码**一行都不用改**，新增功能只是加一个订阅者。

这就是**解耦**，也是事件的核心价值。

## 五、更贴近编程的例子：按钮点击

```csharp
class 按钮
{
    // 按钮只负责：我被点了
    public event Action 被点击;

    public void 点击()
    {
        被点击?.Invoke();   // 喊一声"我被点了"
    }
}

// 主程序：谁想响应谁自己订阅
var 按钮1 = new 按钮();
按钮1.被点击 += () => 弹出提示框("你点击了按钮");
按钮1.被点击 += () => Console.WriteLine("记录日志");

按钮1.点击();  // 按钮不知道谁在听，但所有人都会响应
```

---

## 六、符号速查

| 符号 | 含义 |
|------|------|
| `event` | 声明一个事件 |
| `+=` | "我要听"（订阅） |
| `-=` | "我不听了"（取消订阅） |
| `?.Invoke()` | 安全地"喊一声" |
| 触发事件 | 喊一声 |

---

## 七、总结成三句话

1. **事件 = 一个人喊话，其他人自愿来听**
2. **喊话的人不知道谁在听、听了要干嘛**
3. **好处：以后想加/减响应者，喊话的人不用改代码**

---

## 八、完整可运行示例：门开了

```csharp
using System;

class 门
{
    public event Action 门开了;

    public void 打开()
    {
        Console.WriteLine("门：我被打开了！");
        门开了?.Invoke();
    }
}

class 灯
{
    public void 亮起来() => Console.WriteLine("灯：亮了");
}

class 空调
{
    public void 打开() => Console.WriteLine("空调：开了");
}

class Program
{
    static void Main()
    {
        var 门1 = new 门();
        var 灯1 = new 灯();
        var 空调1 = new 空调();

        门1.门开了 += 灯1.亮起来;
        门1.门开了 += 空调1.打开;

        门1.打开();
    }
}
```

**输出：**

```
门：我被打开了！
灯：亮了
空调：开了
```
