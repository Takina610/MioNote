# 如何保证消息不丢失

首先是通过生产者确认机制，生产者发送消息到交换机后，交换机会回复一个确认消息表示已经收到了；
然后还可以开启持久化机制，将消息存储在硬盘里，消费完成之后再从硬盘中删除；
还有通过消费者确认机制，当消费者确认消费完消息后，会返回一个确认消息给队列，随后队列才删除消息，如果出现异常，则重新发送消息，可以设置为手动发送或者自动发送；
最后是消息的重试机制，如果发送失败了，则重新发送，当然会有一个重试次数，如果超过重试次数，则直接丢弃该消息。

# 如何解决消息重复消费问题

可以给每个消息设置一个唯一 ID，从而来判断是否消费过；
也可以根据幂等方案，比如通过加分布式锁或数据库锁来解决。

# 死信交换机是什么，延迟队列怎么实现

死信交换机用于将死信路由到死信队列中，如果某个消息超时、被拒绝或者队列满了，都可能成为死信；
可以通过死信交换机 + 过期时间TTL 来实现，为需要延迟发送的消息设置一个过期时间，过期后被路由到死信队列，再通过绑定到死信队列的消费者消费；
还可以下载 RabbitMQ 官方提供的延迟队列插件。

# 消息如果过多导致堆积怎么办

首先可以提高消费者的数量；
还可以在消费者使用线程池进行消费；
提高队列的容积，比如使用惰性队列，惰性队列就是可以将消息先放入磁盘中，等到要消费时再从磁盘中放到内存里。
