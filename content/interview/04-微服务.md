# SpringCloud 有哪些组件

有**注册中心**：nacos；
**负载均衡**：Spring Cloud Load Balance；
**远程调用**：open feign；
**服务保护**：sentinel；
**网关系统**：Spring Cloud Gateway

# nacos 是什么

nacos 是**注册中心**，支持服务注册，服务发现，心跳检查等功能；
与其他注册中心不同的是，
nacos 还支持主动询问服务的状态；
还有推送最新的服务列表给消费者；
还支持 AP、CP 模式互相切换；
此外，**nacos 还有配置中心**。

# 讲讲负载均衡

负载均衡就是将请求按照某种策略分摊到各个服务器上，避免单台服务不可用导致全局不可用的情况。
我学过的负载均衡就是 Spring Cloud Load Balance。
负载均衡常见的策略就是：
1. 第一个就是**轮询**，通过注册中心拿到服务列表，将请求一个一个的给服务；
2. 第二个就是**随机**，将请求随机给到这些服务；
3. 还有就是**根据某些指标来进行分配**，比如服务的响应时间、服务设置的权重等；
4. 按照区域进行负载均衡，优先选择同一区域的服务进行处理。

# 服务雪崩是什么

就是**当一个服务宕机或者负荷运行时，可能会导致整条链路的服务都宕机，从而导致整个微服务都变得不可用**；

可以通过配置服务熔断和服务降级的方式进行解决：
**服务熔断**默认是关闭的，可以设置一段时间内的请求失败率来触发熔断，熔断发送后，请求会直接返回错误信息，防止继续请求下游服务；一段时间后熔断器再触发几个请求查看服务是否恢复正常；
**服务降级**就是当服务出问题的时候，给用户一个兜底方法，不至于直接报错，先确保核心功能的可用。

# 限流是什么

**限流就是限制流量**，防止在服务高峰期时，过多的请求过来导致压垮服务器；
可以使用 ngnix 进行限流，添加配置即可；
也可以使用 redis、Spring Cloud Gateway、Sentinel等进行限流；

常见的限流算法有：
**漏桶**算法：将发送来的先放进一个桶里缓存着，这个桶以固定的速率漏出这些请求，就相当于以固定的速率处理这些请求，桶如果满了，就将请求抛弃或者拒绝；
**令牌桶**算法：系统会根据配置每秒生成对应数量的令牌，将其存放到令牌桶里，发送过来的请求申请从桶里拿到令牌，只有拿到令牌的请求才可以被服务器处理。

# CAP、BASE 是什么

CAP 就是**一致性、可用性、分区容错性**；当出现分区错误时，一致性和可用性只能达成一种，不能同时满足；
BASE 就是**基本可用、软状态、最终一致性**。
通常只能选择 AP 和 CP，AP 保证高可用，最终达成一致性；CP 保证一致性，但会出现短暂的不可用状态。

# 分布式发服务的接口幂等性如何设计

接口幂等性就是多次调用 接口或方法不会改变业务状态，可以保证重复调用的结果和单次调用的结果一致；

我们是通过 token + redis 的方式实现的，用户在操作时，后端生成一个 token 存入 redis 里，并且返回前端，后续再进一步操作时，前端携带这个 token 进行校验，如果存在则进一步处理业务，处理完后删除这个 token，不存在则返回错误信息。
