# 什么是程序计数器

程序计数器是线程私有的，每个线程都存有一份，记录的是当前线程执行到哪个字节码指令，用于上下文切换时找到上一次执行的位置

# 什么是 Java 堆

Java 堆是线程共享的资源，主要存储的是对象实例和数组等，如果内存满了，则会抛出 OOM  错误；
堆中主要由新生代和老年代两个区域组成，新生代存储的是一些刚刚创建，比较新的对象，老年代则存储一些生命周期更长的对象；
在 JDK1.7 中，堆中还有一个永久代，主要存储类信息、静态变量、常量和编译后的代码；
在 JDK1.8 后，将永久代移除了，将这些数据放到了本地内存的元空间中，为了避免内存溢出。

# 什么是虚拟机栈

虚拟机栈是线程运行时所需要的内存，每个栈都有多个栈帧组成，栈帧是线程调用方法所占的内存，每个栈只有一个活动栈帧，表示当前执行的方法；

虚拟机栈不会被垃圾回收，垃圾回收涉及的区域主要是堆，但栈帧弹出后，自然就释放空间了；

如果局部变量是在当前方法内创建且仅在当前方法内使用的，则不会有线程安全问题；如果是作为形参或者返回值使用，则需要考虑线程安全问题；

默认的栈内存是 1024K，栈过大会导致线程数变少；

栈帧过多时会导致内存溢出，栈过大时也会导致。

# 栈和堆的区别是什么

栈是线程私有的，而堆是线程共享的；
栈存储的是局部变量和方法参数等信息，堆存储的是对象实例和数组等；
堆是垃圾回收进行的主要区域，而栈不是；
但栈空间不足时会抛出 StackOverflowError，而堆内存不足时会抛出 OutOfMemoryError。

# 解释一下方法区

方法区是所有线程共享的，主要存储类的信息和运行时常量池；

方法区在虚拟机启动时创建，关闭时释放；

# 什么是直接内存

直接内存是不受 JVM 管理的内存，属于操作系统层面的；
常用于 NIO 等操作，用于数据缓冲区，分配和回收的成本较高，但是读写性能高。

# 什么是双亲委派模型

加载某一个类时，当前的类加载器先不会加载，而是一直委托给上一级的加载器，直到委托到顶层的 Bootstrap ClassLoader；如果父加载器加载不了，则将自己加载。

JVM 有三种内置加载器：
1. Bootstrap ClassLoader，由 C++ 实现的，这是最顶层的加载器，主要加载一些最核心的类；
2. Extension ClassLoader，由 Java 实现的，主要加载一些扩展类；
3. Application ClassLoader，同样由 Java 实现的，主要加载一些我们自定义的类

双亲委派模型可以避免一个类被重复加载，如果父类已经加载了，则当前加载器就不需要加载了；
也可以避免类库 API 不被侵入，保证安全。

# 说一下类加载的过程

1. 加载，查找和导入 class 文件
2. 验证，保证加载类的准确性
3. 准备，为类中的变量分配内存并设置初始化值
4. 解析，把类中的符号引用转换为直接引用
5. 初始化，对类的静态代码块，静态变量执行初始化操作
6. 使用，JVM 从入口方法开始执行的用户的程序代码
7. 卸载，当用户的程序代码执行完毕后，开始销毁创建了的 class 对象

# 对象什么时候可以被垃圾回收

当一个对象没有任何引用或者被引用时，那么该对象就可以被垃圾回收了；

常见的垃圾回收算法有：引用计数法、可达性分析：
1. 引用计数法：当一个对象被引用时，就在该对象头上增加一次引用次数，如果该对象的引用次数为 0，则可以被垃圾回收。但如果出现循环引用的问题，则可能导致对象无法被回收。
2. 可达性分析：将某个对象作为根对象，也就是 GC ROOT，执行对象的引用链，如果有对象没有被执行到，则该对象可以被垃圾回收。Java 中的虚拟机都是采用可达性分析。

哪些对象可以作为 GC ROOT？
1. 虚拟机栈中的引用对象
2. 方法区中类静态属性引用的对象
3. 方法区中常量引用的对象
4. 本地方法栈中 JNI 引用的对象

# JVM 的垃圾回收算法有哪些

1. 标记清除算法：首先通过可行性分析标记哪些是可以回收的对象，然后直接清除；这个方法效率高，但是会留下内存碎片，不利于后续空间的分配。
2. 标记整理算法：依旧通过可行性分析标记哪些是可以回收的对象，然后再再将已经分配的区域和未分配的区域进行整理；这个方法不会有大量的内存碎片产生但是对象需要移动，效率偏低。
3. 复制算法：将内存划分为两块区域，每次只使用其中一块，正在使用的对象复制到另一块，然后清除当前内存空间；这个方法的内存使用率较低。

# 讲一下 JVM 中的分代回收

JVM 将堆分为了两个区域，新生代和老年代；
其中新生代又分为了伊甸园区和幸存者区；
幸存者区又分为了 S0 和 S1 区；
首先创建的对象先放入伊甸园区和 S0 区，经过垃圾回收后，将伊甸园区和 S0 的存活对象复制到 S1 区，清空伊甸园区和 S0 区的空间；
又经过垃圾回收后，将伊甸园区和 S1 区的对象复制到 S0 区，清空伊甸园区和 S1 区的空间；
如此反复，如果有对象被复制了 15 次及以上，则将该对象移动到老年代，表示存活时间较长的对象；
如果幸存区提前内存不足或者该对象占用的空间比较大，则可能提前移动到老年代。

Minor GC 发生在伊甸园区满时，只会对新生代的区域进行垃圾回收；
Mixed GC 会同时回收新生代和老年代部分区域的对象，这个 G1 收集器特有的；
Full GC 则是对新生代和老年代全部区域的回收，STW 时间长，所有应该尽量避免出现。

# 强、软、弱、虚引用有什么区别

1. 强引用就是默认的引用类型，使用 new 对象就是强引用；该引用永远不会被 GC 回收。
2. 软引用需要搭配 SoftReference 使用，当内存不足时才会被 GC 回收，常用于缓存对象的使用。
3. 弱引用需要搭配 WeakReference 使用，只要触发了 GC 就会被回收，ThreadLocal 的底层使用了虚引用。
4. 虚引用不能直接获取对象，一般的业务场景根本用不到。
