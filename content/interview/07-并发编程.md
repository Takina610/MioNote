# 进程和线程有什么区别

进程包含线程，进程是操作系统调度的基本单位，而线程是 CPU 调度执行的基本单位；
每个进程独立占用一块内存空间，进程中的线程共享同一块内存；
线程是轻量级进程，在上下文切换的过程中线程更加轻量。

# 并行和并发有什么区别

并发指的是单核 CPU 下多个线程通过时间片调度来运行的过程，宏观上是并行的；
并行指的是多核 CPU 处理不同的线程任务。

# 创建线程的方式有哪些

我们项目是通过线程池来创建线程的；
还有可以通过集成 Thread 类来创建；
还有就是实现 Runnable 接口和 Callable 接口来实现。

# Runnable 和 Callable 有什么区别

Runnable 接口实现的 run 方法是没有返回值的；
而 Callable 接口实现的 call 方法是必须要有返回值的；
Callnable 需要搭配 Future 和 FutureTask 来使用；
Callable 实现的 call 方法可以在方法上直接抛出异常；
Runnable 实现的 run 方法不可以在方法上直接抛异常。

# run 和 start 方法有什么区别

调用 run 方法并没有真正的创建线程，而是单纯的执行方法；
只有调用 start 方法才真正创建了一个线程执行去执行 run 方法的逻辑；
所以 start 方法只能调用一次，而 run 方法可以调用多次。

# notify 和 notifyAll 有什么区别

notify 方法用于随即唤醒一个 wait 的线程；
notifyAll 用于唤醒所有 wait 的线程。

# wait 和 sleep 方法有什么区别

1. sleep 方法是 Thread 的静态方法，而 wait 是 Object 的成员方法，所有对象都可以使用。
2. wait 和 sleep 都让线程休眠对应的时间；
3. wait 方法必须在 synchronized 代码块里执行，也就是必须搭配对象锁一起使用，sleep 方法则没有限制；
4. wait 方法执行后会释放当前线程的锁，可以被 notify 主动唤醒，sleep 方法执行后不会释放当前对象的锁。

# 如何停止一个正在运行的线程

1. 使用一个标志进行打断，比如使用 boolean flag；
2. 使用 stop() 方法，但已废除；
3. 使用 interrupt 方法打断。

# 讲讲对 synchronized 的理解

synchronized 是一个自适应的互斥锁，其可以用在方法上和代码块里；
synchronized 不是一开始就是重量级锁，而是会经过一个锁升级的过程，最开始是偏向锁，只是做一个标记，并不是真正的加锁，如果有其他线程进行竞争，则升级为轻量级锁，也就是自旋锁，如果竞争变得激烈，则继续升级为重量级锁。
它的底层是 monitor 实现的，其是 JVM 层面的，在加锁和解锁的过程中涉及到用户态和内核态的切换，所以比较消耗性能；
monitor 的底层维护三个变量，第一个是 owner，用来表明当前哪个线程持有锁；第二个是 entryList，用于存储状态为 blocked 的线程；最后一个是 waitSet，用于存储状态为 wating 的线程。

# CAS 是什么

CAS 是乐观锁思想的具体思想，在无锁状态下实现数据交换的原子操作；
CAS 的底层是调用 Unsafe 类中的方法，具体实现是 C++ 实现的。

乐观锁是假设不会发生冲突，在访问共享变量时不会真正加锁，如果变量真的被修改，则触发重试操作；
悲观锁就是假设会发生冲突，直接通过加锁防止数据出现不一致的情况。

# volatile 关键字是什么

volatile 用于修饰共享变量，可以使被修饰的变量保证线程间的可见性，防止编译器进行优化，让线程对该变量始终可见；
volatile 还可以防止指令重排序。

# AQS 是什么

AQS 是多线程队列同步器，是一种锁机制，它作为一种基本框架使用，像是 ReentrantLock、Semaphore 等都是基于 AQS 实现的；
AQS 内部维护一个先进先出的双向队列，队列中存储的是等待锁的进程；
AQS 通过维护一个 state 状态来表明是否有线程获取了锁，如果为 0，则表明为无锁状态，1 则表明有线程获取了锁；
线程通过 CAS 操作来修改 state 的状态。

# synchronized 和 Lock 有什么区别

1. 首先 synchronized 是关键字，而 Lock 是接口，在使用时，synchronized 在退出代码块时可以自动释放锁，而 Lock 需要手动调用 unlock() 方法释放锁；
2. 两者都是基于悲观锁的思想实现的，都具备锁的基本功能，如互斥、同步、可重入；Lock 提供更多的功能，比如公平锁、可打断锁、可超时锁等；Lock 锁的实现有 ReentrantLock、ReentrantReadWriteLock(读写锁)，可以适合多种场景；
3. 在锁竞争不激烈的场景下，synchronized 的性能更好，因为其有锁升级的优化；在锁竞争激烈的场景下，Lock 的性能更好。

# 死锁产生的条件是什么

首先锁是互斥的、同一时刻只有一个资源可以拿到锁；
然后就是该锁是不可剥夺的，在拿到锁后，除非当前线程主动释放，否则其他线程拿不到该锁；
其次就是持有并等待，当前线程拿到锁后，还想要获取另一把锁；
最后是出现循环等待，多个线程之间互相获取锁，且形成了环形时。

可以银行家算法来避免死锁；
还可以使用 jps、jstack 等命令，以及 jconsole 等工具进行排查。

# 说一下 ConcurrentHashMap

ConcurrentHashMap 是多线程版本的 HashMap，在 jdk1.7 中，是通过分段数组 + 链表进行实现的；其采用分段锁，对每一个分段进行加锁，底层是 ReentrantLock；
在 jdk1.8 中，进行了重构，变成了和 HashMap 一样的实现，使用 CAS 添加新的节点，采用 synchronized 锁住链表头节点或者红黑树根节点，比分段锁的粒度更细，性能更佳。

# 讲一下线程池

构造线程池的核心参数有 7 个：
1. 第一个是 corePoolSize，就是核心线程数，主要负责进行执行提交到线程池的任务；
2. 第二个是 maximumPoolSize，就是最大线程数，当核心线程被占满时，会创建临时线程执行任务，但最大只会创建最大线程数减去核心线程数的数量；
3. 第三个是 keepLiveTime，就是临时线程的存活时间，如果临时线程超过这个时间还是处于空闲状态，那么就会被销毁；
4. 第四个是时间单位，临时线程存活时间的时间单位；
5. 第五个是阻塞队列，用于存储核心线程占满时，等待的任务；
6. 第六个是线程工厂，用于创建线程；
7. 第七个是拒绝策略，用于阻塞队列满时和所有线程都被占满时，对于提交来的任务如何处理的策略：
  - AbortPolicy：直接抛出异常，这也是默认的策略；
  - CallerRunsPolicy：由主线程执行当前任务；
  - DiscardOldestPolicy：抛弃阻塞队列最先进入的任务，再存入当前任务；
  - DiscardPolicy：直接抛弃当前任务。

具体的执行流程是：
先判断核心线程是否全部占满，如果有空闲线程，则直接执行当前任务；
如果没有，则存入阻塞队列等待；
如果阻塞队列以及存满，则根据核心线程数和最大线程数创建临时线程；
如果不能再继续创建临时线程，则根据拒绝策略对当前任务进行处理。

# 线程池常见的阻塞队列有哪些 (1次)

主要就是 ArrayBlockingQueue 和 LinkedBlockingQueue；
ArrayBlockingQueue 的底层就是一个数组，在创建时需要指定容量大小，初始化时就会创建一个 Node 数组，入队和出队时都会锁住整个数组；
LinkedBlockingQueue 的底层就是链表，在创建时可以不指定容量大小，默认大小是 int 的最大值，其有两把锁，分别在头尾，入队和出队时加不同的锁，所以相比 ArrayBlockingQueue 的性能更高。

# 如何确定核心线程数

1. 如果当前执行的场景是高并发但是执行时间较短，为了避免过多的线程上下文切换，核心数可以设置的少一点，一般是：CPU 核心数 + 1；
2. 如果是并发不高但是执行时间较长的任务，那么就需要看是 IO 密集型任务还是 CPU 密集型任务；如果是 IO 密集型任务，比如网络请求、IO 请求等，可以将线程数设置的多一点，一般是 2 * CPU 核心数 + 1；如果是 CPU 密集型任务，比如序列化转换之类的操作，一般设置为 CPU 核心数 + 1；
3. 如果是高并发且执行时间长，那么就得看整体架构的设计了，比如是否可以缓存某些场景的数据或者直接提高硬件的配置，当然也可以参考第二点。

# 为什么不建议使用 Excutors 创建线程

因为默认都有 int 最大值的情况，可能导致 OOM。

# 说一下 ThreadLocal

ThreadLocal 实现了线程间资源的隔离，避免了各个线程由于争抢共享资源而导致的线程安全问题；ThreadLocal 还实现了同一个线程内资源的共享；**ThreadLocal 是将一个资源包装成一个线程内的资源的**；

底层原理是每一个线程都有一个 ThreadLocalMap，将 ThreadLocal 对象本身作为 Key，Value 就是需要存储的资源；

主要就是有三个方法：
1. 第一个是 set() 方法，首先拿到当前线程的 ThreadLocalMap，通过当前 ThreadLocal 对象作为 Key，将资源作为值进行存储；
2. 第二个是 get() 方法，同样先拿到当前线程的 ThreadLocalMap，再通过 ThreadLocal 对象作为 Key，拿到对应的 Value；
3. 第三个是 remove() 方法，就是将 ThreadLocal 存储的资源进行移除。

ThreadLocalMap 底层是一个 Entry 数组，该 Entry 类继承了 WeakReference 类，也就是弱引用，但只是将 Key 包装成了弱引用，其 Value 还是强引用，所以在垃圾回收时，会出现 Key 被清理了，但是 Value 没被清理的情况，从而导致内存泄漏的问题；所以我们需要主动调用 remove() 方法手动清理资源。
